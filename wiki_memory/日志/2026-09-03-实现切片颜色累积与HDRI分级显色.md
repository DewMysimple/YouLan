# 2026-09-03｜实现切片颜色累积与 HDRI 分级显色

- 类型：`feature`
- 状态：实现及自动验证完成，视觉参数仍可由用户调整。
- 目标：用户要求结合 Three.js 资料搜索与代码实践，使同一种紫色随实际穿过的切片数逐级加深；过程中追加反馈：白底可见分级，HDRI 背景下不明显。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 事实与边界

- 用户要的是实际重叠产生的深浅，不是按距离、复制编号或总数量分别给副本改色。
- 保留外框、内框原色 `#f3faff` / `#d1bfff` 与原有物理参数、两个独立控制。未修改 Blender、GLB、本地 Three.js 示例核心和本地 Blender 仓库。
- 本任务扩展 [[决策/ADR-004-HDRI与可叠加基础阵列|ADR-004]] 的显示能力；仍不是逐层多次折射或光线追踪。原有玻璃模式可以切回。
- 以下算法与初始艺术参数为本轮实现选择，不将其另立为用户已确认的长期 active 决策。

## 资料与判断

- [Three.js 透明排序说明](https://threejs.org/manual/en/transparency.html)：对象排序不能自动解决一个合并 Mesh 内的透明三角形排序。
- [MeshPhysicalMaterial 文档](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)：透射和普通 alpha 混合不同，体积吸收由衰减参数描述。
- [Three.js 透射着色器源码](https://github.com/mrdoob/three.js/blob/dev/src/renderers/shaders/ShaderChunk/transmission_pars_fragment.glsl.js)：用 Beer 定律的指数形式衰减光线；单次体积采样不等同于穿过整个透明阵列。
- [Material 扩展接口](https://threejs.org/docs/pages/Material.html)：通过 `onBeforeCompile` 和 `customProgramCacheKey` 扩展 WebGL 内置材质。
- 同时核对仓库锁定的 r186dev `renderTransmissionPass`：背景/不透明物体采样和双面背面补偿没有建立完整逐层累积。未以网上 dev 版本替换本地版本。
- 没有选择仅降低 opacity 或关闭 depthWrite：不能解决单 Mesh 内透明顺序，也会改变原有玻璃参数。没有选择每份一个完整折射渲染通道，避免 100 份产生同量级的离屏渲染次数。

## 实现与文件

- `src/viewer/sliceAccumulation.js`：新增覆盖计数与着色扩展。半浮点 RG 通道分别累计外框和内框的正面覆盖次数；仅渲染一个进入表面，避免把薄片前后面算成两层。加法混合不依赖副本绘制顺序。
- 主展示仍为一个 Mesh、两个 groups、原有两个物理材质。离屏计数使用内部代理 Mesh，与展示 Mesh 共享同一 geometry，不复制顶点缓冲、不加入主场景。
- 在每个像素，额外层数为 `max(count - 1, 0)`。按原材质线性 RGB 的负对数生成吸收系数，乘槽位 opacity/transmission；软上限指数为 `limit * (1 - exp(-extra * strength / limit))`。
- 只扩展透射颜色，不改镜面反射计算；避开 `FLIP_SIDED` 背面通道，防止透射预处理重复染色。单件或强度为零时绕过计数渲染，清理离屏纹理。
- `src/viewer/viewerPanels.js`、`createSpecimenViewer.js`：在“渲染设置”增加“切片颜色累积”“累积强度”“加深上限”“HDRI 分级显色”。本轮默认启用，强度 0.18，上限 3，显色 0.75。参数不持久化。
- HDRI 分级显色是显式的艺术化可读性补偿：仅图片背景下，在存在额外吸收的切片区域向同一材质的中性白光透射参考混合，然后继续吸收；不替换 HDRI、不模糊模型外背景、不改材质原色。设为 0 保留未增强的累积透射细节。强度越高，透过多层切片的背景纹理越弱；不宣称为物理散射。
- 使用 `make-interfaces-feel-better` 保持原生 lil-gui 的状态、禁用反馈与等宽数字，不新建样式体系、不增加动画。测试截图等待现有折叠动画结束。
- React 清理恢复 shader hooks、释放计数材质和 render target；支持检测不足时显示提示并保留原渲染。
- 新增 `tests/sliceAccumulation.test.js`、`tests/browserHarness.mjs`、`tests/browser-slices.mjs`；现有浏览器回归更新状态行数量。

## 验证

- `npm test`：13 项通过，包含单片零增益、2–256 层单调软饱和、双槽系数与参数不变、着色器补丁、能力不足回退、离屏异常恢复及重复释放。
- 真实 Chrome + Vite：1、2、5、10、30、100 层中心像素依次加深；读取半浮点计数确认 100 片是 100 而非 200。零间距 100 份同样正确累计。
- 白色环境中心 RGB：1 片 `(192,169,226)`，10 片 `(162,123,227)`，100 片 `(123,79,227)`。从反面看 100 片得到相同中心像素；单片开关和横向无重叠排列的采样不变。
- 索引内三角形提交顺序反转不改变覆盖计数；主场景单 Mesh、两个 groups 不变，代理共享相同 geometry。
- HDRI 显色开关：模型外采样一致，内部采样发生变化；隐藏图片背景后显色值不影响像素。背景照明独立、旋转与各槽环境强度继续有效。
- 验证侧视、OrbitControls、opacity=0、强度=0、上限调整、透射分辨率 0.25、连续 8 次模式开关、100%/200% 像素密度和移动端控件。
- 计数额外 2 次绘制，与副本数无关；连续模式切换 GPU 纹理数量稳定，静止不增加渲染帧。未将此作为所有设备的帧率保证。
- 原完整 HDR/EXR/JPG/PNG/UltraHDR、加载竞争、2×3/256 份上限、双槽独立、几何恢复、移动端和卸载回归通过。
- 生产构建通过；独立 Vite preview 中再次验证 100 份白色/HDRI 环境、原色和无浏览器错误，白底中心像素与开发构建一致。仍有既有的主包大于 500 kB 提示。
- 浏览器截图和报告输出到独立临时测试目录，未把测试图/配置写回应用默认资产。

## 剩余限制

- 沿相机直线视线计数，不追踪折射后的弯折路径；大厚度、强折射、相机位于实体内部、复杂相交形状仍需专门渲染方案。
- 显色补偿和软上限是可调的美术处理，不是完整物理玻璃解算；不会在本轮自动追加参考图中的蝴蝶、泛光、粉黄天空等内容。
- 保留用户已有的 `source/Specimen_Frame_Transparent_Merged.blend` 删除，不纳入本次提交。
